# Operational Logging Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Diagnose requests, committed mutations and worker progress safely.

**Architecture:** Standard Python loggers in application/inbound adapters, ASGI
request context, and shared console configuration at process startup. Domain and
database transaction semantics remain unchanged.

**Tech Stack:** Python logging/contextvars/json, FastAPI/ASGI, Uvicorn, pytest.

**Spec:** docs/superpowers/specs/2026-11-01-logging-design.md

## Global Constraints

- LOG_LEVEL defaults to INFO; LOG_FORMAT defaults to text, supports json.
- Never log credentials, bodies, raw paths/query strings, raw idempotency keys or arbitrary exception messages.
- Success events follow transaction exit, retries carry reused outcomes.
- Preserve the user's container.py edit and exclude it from commits.
- Work on feature-logging in the existing checkout; no new worktree requested.
- One final local feature commit after required validation, per feature-workflow.

## Review Focus

- Reload/container startup must use the same configuration as local startup.
- Exceptions and malformed/unmatched routes must not leak caller input.
- Concurrent request context must reset after errors and cancellation.
- Commit failure must never produce a success event.
- Worker fallback, partial failure and cancellation must report honest counts.
